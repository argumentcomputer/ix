# Recursive fixed-table evaluation

The [results](../../../docs/IxbyRecursiveTuning.md) and
[checked report](../cslib-runtime-v2-recursion.json) compare the original Flock
circuit-structure evaluator with the optimized evaluator on the same three
`cslib-2048` leaf proofs. The range is physical clocks 0–20,000, covering 4,598
logical steps. Both trees include the leaf-pair join and the subsequent
recursive-node/leaf join.

The change computes exactly the same matrix marginals. Both joins retain their
setup identities and produce byte-identical proofs, statements and deferred
claims. A separate process recompiles the approved root setup and verifies the
root, including rejection of all 114 tested public-word mutations, truncation
and trailing data.

## Evidence

- `reference-chain.log/.time` and `optimized-chain.log/.time`: matching runs
  of the same test binary, including setup, every join and fresh reception.
- `discovery-chain.log/.time`: the initial instrumented run that located the
  native fixed-table bottleneck, before the optimized evaluator was added.
- `recursive-tests.log`, `structure-tests.log`, `recursive-clippy.log`:
  completed regression, differential and strict lint checks.
- `measurement.json`: source, binary, log and artifact receipts and run policy.
- `proofs/range-0-2.flock/.statement`: the identical pair proof and statement.
  The identical final root is already retained as
  [cslib.flock](../cslib-tuning-v0/roots/cslib.flock) and
  [cslib.statement](../cslib-tuning-v0/roots/cslib.statement).

The original three leaf proofs remain in the experiment directory; their
receipts are also in the earlier [leaf measurement](../cslib-runtime-v2-tuning.json).
The new report checks each leaf receipt before adding its earlier witness,
proof and verification timing to the newly measured joins. Leaf timings are
reused, rather than measured again in this experiment.

Logs retain measurements verbatim, with trailing blank lines removed.
The discovery run predates the per-family timers and `PCS_TRACE` output.
The final comparison uses the same binary and profiling options in both modes.
Ordinary checks overlapped optimized setup compilation. Large proof jobs ran
sequentially, with one proof worker, two Rayon threads, an 84 GiB memory cap
and swap disabled on the same Ryzen 9 7950X3D host.

## Reproduce

Start with the three verified `cslib-2048` leaf records generated by the
[equal-work leaf benchmark](../cslib-tuning-v0/README.md#equal-work-proofs-and-all-recursive-joins).
All commands below run from the repository root and use Bash. Offline Cargo
requires the pinned dependencies to be available locally.

```bash
experiment=$(mktemp -d /tmp/ixby-recursion.XXXXXX)
leaf_dir=/path/to/cslib-proofs
timer=$(type -P time)
cargo test --offline --locked --release --manifest-path flock-stage4/Cargo.toml \
  -p ix-flock-recursion --lib --no-run --message-format=json > "$experiment/build.jsonl"
python3 - "$experiment" <<'PY'
import json, shutil, sys
from pathlib import Path
p = Path(sys.argv[1])
entries = [json.loads(s) for s in (p / "build.jsonl").read_text().splitlines()]
binaries = [e["executable"] for e in entries
            if e.get("executable") and e["target"]["name"] == "ix_flock_recursion"]
assert len(binaries) == 1
shutil.copy2(binaries[0], p / "tree-tests")
PY

for mode in reference optimized; do
  reference_mode=0
  if [ "$mode" = reference ]; then reference_mode=1; fi
  mkdir "$experiment/$mode-chain"
  systemd-run --user --scope --quiet -p MemoryMax=84G -p MemorySwapMax=0 \
    env IXBY_EXECUTION_CHAIN_CLASS=cslib-2048 IXBY_EXECUTION_CHAIN_LEAVES=3 \
    IXBY_LARGE_EXECUTION_PROOFS="$leaf_dir" \
    IXBY_LARGE_EXECUTION_CHAIN_OUT="$experiment/$mode-chain" \
    IXBY_RECURSION_PROFILE=1 IXBY_RECURSION_REFERENCE_STRUCTURE="$reference_mode" \
    PCS_TRACE=1 RAYON_NUM_THREADS=2 MALLOC_ARENA_MAX=2 \
    "$timer" -v -o "$experiment/$mode-chain.time" "$experiment/tree-tests" \
    execution_tree::tests::large_execution::execution_range_chain_proves_fresh \
    --exact --ignored --nocapture > "$experiment/$mode-chain.log" 2>&1
done

python3 -B flock-stage3/profile/recursive_tuning.py --root "$experiment" \
  --leaf-report flock-stage3/profile/cslib-runtime-v2-tuning.json \
  --leaf-dir "$leaf_dir" --binary "$experiment/tree-tests" \
  --run reference --run optimized --out "$experiment/report.json"
```

The reference switch exists only in the test build. Production always uses
the optimized evaluator. Both paths use the pinned Flock revision
`b310f35f35f68095537150a1c8c0a43caca9a29e` and the same table definitions.
The fresh receiver clears the environment and uses the optimized default in
both runs. The reference switch covers the producer's folds and its explicit
verification of each completed node. This also checks that the production
receiver accepts the original evaluator's byte-identical proofs.

When regenerating leaves, pass the report produced by that leaf run to
`--leaf-report`. The assembler requires the supplied leaf files to match that
report. The recorded run reused exactly the earlier archived leaf measurement.

## Reading the profile

`IXBY_RECURSION_PROFILE=1` writes JSON records with a process ID, scope ID,
phase, wall seconds and optional constraint counts. The scopes include child
transcript hashing, statement binding, wiring, Boolean/element algebra,
commitment-opening checks, native fold generation, Flock proving and root
table discharge. Graph counts measure circuit work; their emission times
measure native advice generation.

`node_prove` and `node_verify` partition each join's wall time. The `child`,
`fold`, `fold_family` and `native_proof` scopes provide nested detail and must
not be added again to the parent scopes. `PCS_TRACE=1` adds Flock's own kernel
timings; some phases run concurrently, as indicated in those lines.

`recursive_tuning.py` requires both completed producer/receiver test results,
successful process exits, adjacent leaf endpoints, every canonical join,
matching setup identities, and identical proof/statement receipts across
evaluators. It also checks that compilation and advice emit the same counts.
The script validates recorded evidence; Flock proof verification is performed
by the Rust producer and receiver.

To verify the retained final root with the optimized evaluator, use the
[standalone root receiver command](../cslib-tuning-v0/README.md) with the
newly built test binary. The approved class, leaf count, statement and proof
bytes remain the same.
